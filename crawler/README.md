# 赛事线索采集器（crawler/）

自动化"发现赛事线索"，替代人工刷小红书/公众号。抓到的新线索写入网站投稿表，
到后台 `/admin/submissions` 核对「采集线索」（紫色徽章）后正式录入赛事。

## 运行

```powershell
# 全量：25 城 × 全部数据源（最酷约 40 秒，搜狗约 2 分钟）
python crawler/collect.py --source zuicool,sogou

# 单城市 / 指定数据源
python crawler/collect.py --city 南京 --source zuicool,sogou,bing
```

## 数据源

| source | 覆盖目标 | 说明 | 状态 |
| --- | --- | --- | --- |
| `zuicool` | 路跑/越野报名中赛事 | 最酷报名平台各城市页，结构化最好 | **稳定（主力）** |
| `sogou` | 公众号推文 | 搜狗微信文章搜索，Session 预热（ABTEST/SUID）后低频连续请求实测稳定；每城 4 组关键词（马拉松/赛事/越野/联赛 + 报名） | **稳定（公众号主力）** |

> 注：`bing` 源已移除（实测其中国区自然结果几乎不含小红书/公众号直链，无产出价值）。

## 关于小红书与公众号的边界（多轮实测结论）

- **公众号**：搜狗微信搜索可稳定覆盖（Session 预热后 25 城连续请求实测零拦截）；关键词组扩充即线性提升覆盖
- **小红书**：**无可靠的无头采集通道**。四轮实测：必应 site:（HTML/RSS/Cookie 预热均被弱化）、百度（无 Cookie 直接进安全验证）、360（site: 语法可用但收录的小红书内容全是旅游攻略，无赛事笔记）、DuckDuckGo（国内超时）。根本原因：小红书对搜索引擎屏蔽笔记索引，赛事笔记只能在 APP 内看到。推荐流程：手机刷到 → 复制链接/文字 → `/submit` 投稿页录入；长期靠用户投稿沉淀
- 不采用 MediaCrawler 类登录逆向爬虫（封号风险 + 违规）

## 去重与过滤机制

- **体育关键词白名单**：搜索源（sogou）的标题/摘要必须含体育词（马拉松/越野/骑行/联赛…），滤除旅游/百科/奥数等噪声
- **旧文过滤**：标题/摘要中出现的年份全部不是 2026/2027 → 丢弃（如 2020 疫情退费公告）；另排除"疫情/退费/回顾"等历史公告词
- **空标题过滤**：搜狗列表的图片空链接不产出线索
- 与库内 `Event.name` 归一化比对 → 已收录赛事不再重复报
- 与已有线索的来源 URL 比对 → 同一线索只报一次
- 因此**重复运行安全**，每次只产出增量新发现
- 已知残留：完全不带年份的历史推文（如"报名倒计时2天"）会漏进队列，靠后台人工识别（数量少）

## 定时

**推荐**：任务计划每天跑一次轮转模式（分城轮转，单日搜狗请求量降为 1/5，彻底避开频率风控；最酷无风控保持每日全量）：

```
程序：python
参数：D:\Sports Event Data Collection Project\crawler\collect.py --source zuicool,sogou --rotate 5
起始位置：D:\Sports Event Data Collection Project
```

5 天为一个周期覆盖全部 25 城；触发验证码自动跳过当日组、下轮重试，系统自愈。

## 公众号终极方案：微信读书 RSS（推荐部署）

> ### 📌 当前部署状态（2026-10-25 记录）
>
> - ✅ Docker 容器已部署并运行：`wewe-rss`（SQLite 版，端口 4000，授权码 `quanmin2026`，数据目录 `crawler/wewe-rss-data/`）
> - ⏸ **卡在扫码绑定**：添加读书账号时二维码接口返回 502（微信读书服务端对当前出口 IP 风控/瞬态错误，容器网络本身连通正常）
> - **待办（按顺序重试）**：① 重试添加账号（502 可能瞬态）→ ② 电脑连手机热点换出口 IP 后刷新重试 → ③ 隔天再试
> - **容器管理**：启动 `docker start wewe-rss` / 停止 `docker stop wewe-rss` / 日志 `docker logs wewe-rss --tail 30`
> - 扫码绑定成功后：添加公众号订阅 → 复制 feed 地址填入 `crawler/rss_sources.txt` → `python crawler/collect.py --source all` 跑通全链路

搜狗微信是"够用但不稳"的通道（验证码/IP 风控随频率上升）。**彻底稳定的方案是绕开搜狗**：

1. 部署 [wewe-rss](https://github.com/cooderl/wewe-rss)（开源，`npx` 或 Docker 均可，常驻运行）
2. 微信扫码登录一次（偶尔续期）
3. 把 25 城的体育局/赛事/跑团公众号加入订阅 → 每个公众号得到一个 RSS feed 地址
4. 把 feed 地址逐行填入 `crawler/rss_sources.txt`
5. 采集器加 `--source rss`（或 `all`）——结构化 XML 零风控，公众号监控永久稳定

此方案跑通后，搜狗源可降级为备用（`--rotate 10` 拉长轮转周期）。

## 搜狗登录 Cookie（可选加码）

浏览器登录搜狗账号后，F12 → 网络 → 任一请求 → 复制完整 Cookie 头，
存入 `crawler/sogou_cookie.txt`（已被 gitignore）。登录态配额高于匿名会话，验证码概率显著下降。
Cookie 失效（数月）后重新复制即可。

## 后台核对流程

1. `/admin/submissions` 查看「采集线索」（紫色徽章，含时间/地点/平台状态/来源链接）
2. 点 contact 链接核对原文 → 无误则到「赛事管理 → 新建赛事」正式录入
3. 线索本身点「通过」归档（表示已处理）
