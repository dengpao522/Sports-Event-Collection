结论先行

一句话定位：一个由个人运营、把分散在各公众号 / 小程序 / 官网 / 协会通知里的"大众可报名赛事"聚合到一处的网站，让普通人按城市 × 运动品类 × 时间快速找到自己能参加的比赛，并在报名开启/截止前收到提醒。

对"一定要全"的产品回答：不追求一次性全国全品类，而追求在首发城市（上海、杭州）做到"可报名赛事不漏 + 信息差透明"，跑通后再向江浙沪其余城市与全国复制。透明化的三件套是本站差异化核心： ① 待官宣订阅（年度固定赛事先占位、官宣即通知）、② 品类空窗明示（查不到时告诉用户"为什么没有、往年什么时候有"）、③ 找不到就提需求（用户一句话，运营定向补采）。

一、背景与问题

1.1 观察到的问题（已由实际采集验证）

运营方在 2026-10 已实际完成上海、杭州、西安三份赛事清单的采集，过程本身即验证了痛点：

  • 发布通道极度分散。同类赛事散落在体育局官网、赛事公众号、微信小程序（如"最酷""曲江体育"）、协会网站、品牌方公众号、本地宝等十余个渠道，普通用户没有能力逐一跟踪。
  • 信息时效强、窗口短。大量赛事"先报先得、报满即止"，旗舰赛则是抽签制且报名窗口与比赛日相隔数月（如杭州马拉松 7 月报名、11 月开赛），错过即等一年。
  • 存在大量"信息差焦虑"。用户甚至不知道"有这个比赛存在过"；年度固定赛事（如西湖冬泳、新年登高）每年都有，但下一届何时官宣无人提醒。
  • 空窗本身也是信息。采集发现不少品类在特定季节是"真空"（如冬季主城区无路跑大赛、飞盘联赛 5–10 月赛季后收官），用户反复查询却只得到空白结果，体验差且不知道原因。

1.2 受影响的用户与时刻

核心用户是有运动习惯、想参赛但缺乏赛事信息渠道的大众运动爱好者。关键时刻：想找一个"最近、在我城市、我这个水平能报"的比赛时；以及担心错过某场年度赛事报名窗口时。

1.3 产品回应与可观察结果

  • 把分散信息聚合为统一的可筛选赛事列表 + 标准化报名指引，结果可观察：用户在 3 次点击内定位到一场可报名赛事及其官方报名入口。
  • 用提醒解决"错过窗口"，结果可观察：用户订阅后，在报名开启/截止前收到触达。
  • 用空窗明示与待官宣订阅解决"查不到/不知道"，结果可观察：任何筛选结果为 0 的页面，都会给出原因解释或补采入口，而不是空白。
关于主办方不合作的现实：MVP 不把"主办方主动入驻/授权"作为前提。平台只做公开信息的聚合与指引，报名始终跳转官方渠道、不经手费用；待流量形成后，主办方自助发布才是水到渠成的 P1/P2 能力。

二、目标与非目标

2.1 MVP 目标（定性、可观察）

  1. 找得到：在首发的上海、杭州两城，用户能按城市/品类/时间/报名状态检索到当前可报名或即将报名的大众赛事。
  2. 报得上：每场赛事都给出明确的"去哪报、怎么报"的官方操作指引或链接，并标注信息核实时间。
  3. 不错过：对"即将报名 / 待官宣 / 报名中临近截止"的赛事，用户可一键订阅提醒。
  4. 不空白：无结果时给出空窗原因、往年档期或补采入口，把"信息差"显性化。
  5. 可持续更新：运营能用接近现有 Excel 的成本完成录入、批量导入与状态维护，支撑一个人也能运转。

2.2 非目标（MVP 明确不做，防止范围蔓延）

  • 不做站内报名、抽签、收费、退款——报名与资金全部留在官方渠道。
  • 不做职业联赛的资讯流、比分、直播、数据统计。
  • 不做主办方自助发布后台与权限体系（运营单角色即可）。
  • 不做用户社交/动态/组队社区（可作为 P2 探索）。
  • 不以"全国一次铺满"为目标，覆盖度按城市×品类逐步推进。

3.1 角色

运营采集员MVP 阶段即负责人本人进入内部采集台：录入/导入/编辑赛事、审核投稿、维护状态与核实标记、查看覆盖度

3.2 典型场景

  • 场景 A · 就近找赛："这两个月杭州，我能报的跑步比赛有哪些？" → 选城市+品类+时间，看到报名中的赛事与截止时间，点进去按指引报名。
  • 场景 B · 盯年度赛："西湖冬泳元旦都有，今年什么时候开报名？" → 赛事已以"待官宣"占位，用户订阅，官宣后收到提醒。
  • 场景 C · 怕错过截止：某 10K 赛"报名中"，用户怕忘 → 订阅"截止前提醒"。
  • 场景 D · 查无结果："西安冬天有没有羽毛球个人公开赛？" → 页面明确显示该品类当前空窗、往年集中在 8–9 月，并提供"开赛了通知我 / 我要报别的赛"。
  • 场景 E · 共建：用户发现一场运营漏采的比赛或信息有误 → 一键投稿/报错，运营审核后上线。

目的

FR-03赛事详情与官方报名指引

目的

规则

异常
官方链接失效时显示并提供"报错"；待官宣赛事不展示报名按钮，仅展示订阅。

FR-05赛事状态时间线

规则
每场赛事渲染统一五段时间线：待官宣 → 报名中 → 报名截止 → 开赛 → 已结束（延期/取消为旁路红色状态）。当前阶段高亮，已过阶段置绿。状态由"报名开始/截止时间 + 比赛日期"自动驱动，运营可手动覆盖（如报满即止提前额满）。
异常
时间字段缺失（待核实）时对应节点显示"时间待定"，不做错误推断。

FR-06空窗明示与"找赛需求"提交

目的
把"查不到"从失败体验变成信任建设与需求收集——这是"全"的关键补偿机制。
触发
某城市+品类+时间筛选结果为 0，或搜索无命中。
规则
展示"品类空窗卡"：① 空窗原因（赛季已收官/该品类本季个人赛稀少等，由运营按城市×品类维护）；② 往年档期规律；③ 两个动作——"有赛通知我"（绑定该城市×品类，一旦录入新赛事即邮件通知）、"我要找的比赛"（一句话描述，进入运营补采队列）。
结果
提交写入需求池并在采集台按城市/品类聚合计数，指导补采优先级。

FR-07用户投稿赛事 / 信息报错

触发
列表页"我要投稿"、详情页"信息有误？"。
规则
投稿表单（尽量轻）：赛事名、城市、品类、已知时间/链接、投稿人联系方式（选填）。
报错：预置问题类型（时间变了 / 报名已截止或已满 / 链接失效 / 赛事取消 / 其他）+ 补充说明。
所有 UGC 默认不直接上线，进入采集台审核队列；上线后赛事标注"用户线索，已核实"。
异常
反垃圾：同 IP/邮箱限频、必填项校验；违法违规内容在审核环节拦截（见共享规则）。

模块 B · 运营后台（内部，仅运营角色）

FR-08运营采集台

目的
让一个人能用最低成本维持数据"全且新"，直接复用现有 Excel 工作流。
功能
① 赛事增删改：表单字段对齐第 5 章；支持草稿/发布。
② Excel 批量导入：提供与现有三份清单一致的模板（城市/品类/赛事名/比赛日期/地点/报名截止/报名状态/报名方式与备注），导入时做字段映射、必填校验、重复赛事检测，导入结果给出成功/失败/待确认清单。
③ 状态维护：按时间自动推进状态；提供"临近需复核"列表（如截止时间标记了"需核实"、报名中且距今 3 天内）。
④ 投稿/报错审核队列：通过→合并入库；拒绝→可填原因（P1 再做投稿人通知）。
⑤ 找赛需求池：按城市×品类聚合，显示人数，作为补采优先级依据。
⑥ 覆盖度看板：城市 × 一级品类矩阵，显示各格"可报名赛事数 + 最近更新时间"，空格标红，直观回答"哪里还不全"。
规则
每次修改记录最近核实时间与来源；删除为软删除，保留历史赛事用于"来年提醒"与档期规律。

八、共享规则与异常

8.1 状态流转规则

  • 自动流转：到达"报名开始时间"→报名中；到达"截止时间"→已截止；到达比赛日→进行中；比赛日次日→已结束。
  • 待官宣不自动流转，需运营在官宣后补全信息再转即将报名/报名中，转换时自动通知订阅者。
  • 报满即止需运营手动转截止；延期/取消只能由运营依据官方信息设置，并触发变更通知。
  • 时间为"待核实"的赛事不参与自动截止，进入复核列表，避免错误下线。

8.2 信息可信度与展示规则

统一免责声明（详情页固定文案）：本站仅聚合公开信息，不代为报名或收费，一切报名条件、时间与费用以赛事官方最新发布为准。

8.3 提醒触达规则

  • 同一赛事同一节点对同一邮箱最多触达 1 次；变更通知不受此限。
  • 截止提醒默认截止前 24 小时；用户可选 72 小时。
  • 邮件底部必须有一键退订；退订即时生效。

8.4 权限与合规边界

  • 权限：采集台仅运营可访问，URL 不对外暴露；P0 无其他后台角色。
  • 内容合规：仅聚合与转述公开可访问的赛事信息并标注来源、链接回官方，不搬运付费/独家内容，不代收费用，规避版权与资金风险。
  • UGC：先审后发；拦截违法违规、广告引流、虚假赛事；P0 用人工审核即可（量小）。
  • 个人信息：邮箱仅用于赛事提醒，不用于营销；提供退订；隐私政策页在正式收集邮箱前上线（见 11.2 T2）。

九、采集运营机制（产品化视角）

"全"靠运营机制兜底，建议把现有手工经验沉淀为固定信源清单与节奏：

  • 信源库（按城市）：体育局/群体处官网与公众号、各单项运动协会（田协、羽协、棋院等）、主流报名平台（最酷、咕咚、马拉马拉、曲江体育类本地平台）、场馆/俱乐部公众号、本地宝/政务发布。每个城市维护一张信源表。
  • 采集节奏：周度巡检信源 + 节点重点（旗舰赛报名窗口、节庆固定赛 12 月/1 月档）。
  • 年度赛事日历：把已确认的"年度固定赛事"提前以待官宣占位（如西湖冬泳、新年登高、各城马拉松），形成天然的订阅库存。
  • 覆盖度驱动补采：以采集台矩阵空格 + 用户需求池计数决定每周补采方向。

十、P1 与后续演进

  • 账号体系：手机号/微信登录，云端收藏、订阅管理、"我的赛程"日历。
  • 触达升级：微信服务号模板消息（个人主体无法注册服务号，届时需先升级主体）、浏览器 Web Push。
  • 供给升级：主办方自助发布 + 认领赛事；投稿人激励与通知。
  • 城市扩张：跑通沪杭两城后，第一批扩南京/苏州/宁波，再按需求池热度扩长三角 → 全国。
  • 能力探索（P2，需重新评估）：同水平匹配/约赛、赛事评价、组队社区。
